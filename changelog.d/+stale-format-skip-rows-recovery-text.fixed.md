`moneybin import files --format <name>` and `moneybin import confirm --format <name>` stopping because a real transaction was consumed as the header now name recoveries that exist — re-run without `--format` so the layout is detected fresh from the file, and `moneybin import formats delete <name>` to remove the format that no longer matches — instead of telling you to add a header row the file already has or pointing at a numeric `skip_rows` cause the product cannot know. The printed retry now repeats the options the failed read actually resolved rather than only the flags you typed, so a sheet, delimiter, encoding, date format or number format the saved format supplied survives dropping `--format`; previously an unset sheet made the reader auto-select the largest worksheet, so a workbook whose largest sheet also had compatible headers was silently read from the wrong sheet, and a dropped number format let a re-read reinterpret decimal separators. That corrected text now also reaches an interactive terminal, which fell through to generic advice whose suggested commands re-applied `--format` and re-raised the same refusal, and `moneybin import preview`, which told you to correct the format. The `moneybin import preview` command offered alongside for inspection no longer carries the stale `--format` itself — it previously reproduced the same refusal rather than inspecting anything, on a line printed directly beneath the text telling you to drop that flag. The delete command now carries `--yes`, which a script or agent needs to get past its confirmation prompt — drop the flag to be asked first. The message says the retry repeats the same read *options* rather than claiming an identical read: a saved format's trailing-row patterns have no command-line equivalent to carry, though no saved format currently records one.
