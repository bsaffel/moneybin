`moneybin import files --format <name>` and `moneybin import confirm --format <name>` stopping because a saved format's `skip_rows` consumed a transaction as the header now name recoveries that exist — re-run without `--format` so the header is detected fresh, and `moneybin import formats delete <name>` to remove the format — instead of telling you to add a header row the file already has or to correct a `skip_rows` no command edits. The printed retry now repeats the options the failed read actually resolved rather than only the flags you typed, so a sheet, delimiter, encoding, date format or number format the saved format supplied survives dropping `--format`; previously an unset sheet made the reader auto-select the largest worksheet, so a workbook whose largest sheet also had compatible headers was silently read from the wrong sheet, and a dropped number format let a re-read reinterpret decimal separators. That corrected text now also reaches an interactive terminal, which fell through to generic advice whose suggested commands re-applied `--format` and re-raised the same refusal, and `moneybin import preview`, which told you to correct the format.
