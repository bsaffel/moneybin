An MCP server no longer fails to start while another server on the same profile runs the post-upgrade schema heal. MCP hosts such as Claude Desktop start more than one server per profile. When the heal ran past the 10 s lock wait, the second server exited with `Could not acquire write lock`, and the host marked the connection disconnected without retrying. A starting server now waits up to 45 s for a heal already in progress, then re-checks the schema instead of healing it a second time. Any other lock holder still fails at 10 s. A timed-out read-only open now reports `Could not open the database for reading` instead of claiming a write lock, and it names the holder's operation, such as `transform_apply`.
