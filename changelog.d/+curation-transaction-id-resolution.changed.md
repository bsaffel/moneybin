A curation write whose transaction id names no transaction at all — not the id itself, and nothing it forwards to — is now refused with a `transaction_reference_not_found` error instead of being silently accepted. This includes clearing a category, which previously reported success against an id that matched nothing. The refusal now also covers the `transactions_annotate` MCP tool (notes, tags, and splits submitted as a batch) and the guarded categorization write behind `transactions_categorize_commit` and the rule/merchant engine passes — previously only the granular per-field writers and manual category edits carried this check. Removing tags or clearing splits against an unknown id used to be a silent no-op; it now raises the same refusal.
