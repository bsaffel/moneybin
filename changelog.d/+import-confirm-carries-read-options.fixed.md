`moneybin import confirm` now accepts `--format`, `--date-format`, `--number-format`, `--sheet`, `--delimiter`, `--encoding`, `--no-row-limit`, and `--no-size-limit`, and every recovery command MoneyBin prints (from `import files`, `import confirm`, and `import preview`) carries whichever of these options the original invocation used. Previously a retry command dropped them, so re-running it against a file that needed a non-default format, sheet, delimiter, or encoding could read the file differently than the invocation that produced the proposal — and a file over the size or row threshold, which reaches a confirmation only because the caller lifted the limit, was refused outright by its own printed retry. `moneybin import preview` accepts the same two limit overrides for the same reason. On the two paths that cannot honour them they are now handled like every other read option rather than in silence: `import confirm --bridge-response` refuses them, as it already refused the format options, and a PDF `import preview` names them in its "ignored for a PDF" warning.
