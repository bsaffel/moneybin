`reports.net_worth.unanchored_account_count`: `net_worth` (and `total_assets`/`total_liabilities`) is NULL on any date where an account in net worth holds value — a transaction, a trade, or a broker-reported position — but has no balance observation, the way an unpriced currency already NULLs the total. Such an account has rows in `core.fct_balances_daily` with `balance` NULL, from its first evidence to the newest evidence date, so `reports.net_worth_accounts` lists it on every one of those dates with its balance columns NULL and `is_observed = FALSE`. A new `core.*` view, `core.dim_holdings_broker_reported`, reduces each Plaid item's newest holdings snapshot to one broker-reported position per account. Two `moneybin system doctor` checks close the release gate: `net_worth_unanchored_accounts` (`fail`) flags an account in net worth with a NULL balance on the latest date on which any account counts toward net worth, the date `reports.net_worth` reports by default — a balance recorded with `accounts balance assert` clears it, and restores the total, after the next `moneybin refresh` — and `net_worth_stale_balance` (`warn`, threshold `doctor.balance_staleness_threshold_days`, default 30) flags one whose latest observed balance has aged past the threshold without blocking release. Each check sets a gauge, `moneybin_net_worth_unanchored_accounts` and `moneybin_net_worth_stale_balance_accounts`, and lists its accounts as masked `account:<id>` entries. See [`net-worth-guard-on-daily-balances.md`](docs/specs/net-worth-guard-on-daily-balances.md).
